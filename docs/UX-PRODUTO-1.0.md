# UX de produto SkinClinic 1.0

**Data:** 2026-09-20  
**Promessa na tela:** “Da avaliação ao resultado, tudo conectado.”  
**Pergunta de ouro:** “Qual é a próxima coisa importante que o usuário precisa fazer?”

---

## Hierarquia (toda tela operacional)

1. O que aconteceu?  
2. O que precisa de atenção?  
3. O que pode melhorar?  
4. Qual ação pode ser tomada?

O cockpit do dashboard (set/2026) já aponta nessa direção. Os cards globais do header **competem** com ela — consolidar (P1).

## Personalidade

Moderno, rápido, confiável, premium, simples. Referências de mercado (Clínica/Boulevard/agenda humana), não software administrativo dos anos 2000.

Mobile-first para: marcar, confirmar, registrar protocolo, receber.

Desktop para: margem, metas, DRE, equipe.

## Jornada do gestor (alvo)

Abrir → Hoje (atenção) → Agenda do dia → registrar aplicado → ver margem em risco se houver.

## Jornada da recepção

Agenda + cliente + confirmação. Sem Marketing/IA/Exportar na raiz.

## Jornada do profissional

Ficha: anamnese → plano → protocolo aplicado. IA preliminar nunca no cliente.

## Portal = Minha jornada (P2)

Avaliação, anamnese, plano (o que foi combinado), sessões, evolução, skincare liberado, próximos passos, agenda, documentos. Só o validado.

## Prévia vs produção

`preview/ux-clinica.html` (personalidade Apple/Clínica) **não está no deploy**. Produção ainda é o tema Inter/indigo. Unificar visual **depois** de P0, sem quebrar fluxos.

## Anti-padrões

Dashboard lotado de gráficos sem ação. `alert()` no onboarding. Menu com 15 itens iguais. Segundo Copilot no centro da tela.
